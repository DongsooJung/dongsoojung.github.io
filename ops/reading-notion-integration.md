# 밀리의 서재 독서기록 통합 운영계획

## 목표

`/reading/`에서 노션의 `밀리의서재 도서목록` 598권과 `독서 LOG & 독후감`을 하나의 디지털 서재로 탐색하게 한다. 노션을 원본 관리 시스템으로 유지하고, 공개 웹은 정적 JSON 스냅샷을 사용해 속도와 장애 격리를 확보한다.

## 공개 및 연결 규칙

- 도서목록은 `웹공개 = true`이며 도서명이 있는 항목만 공개한다.
- 독서기록은 `웹공개 = true`이고 상태가 `완독` 또는 `재독`인 항목만 공개한다.
- 도서와 독서기록의 정식 연결키는 노션 페이지 ID와 관계 속성(`독서LOG`/`관련도서`)이다.
- 관계가 아직 비어 있는 기존 기록은 정규화한 제목이 도서목록에서 정확히 한 권과 일치할 때만 임시 연결한다. 후보가 없거나 둘 이상이면 연결하지 않는다.
- 연결된 독서기록의 상태를 도서목록 체크박스보다 우선해 읽음 상태를 표시한다.

## 데이터 흐름

1. GitHub Actions가 매일 또는 수동 실행으로 두 노션 데이터소스를 조회한다.
2. 독서기록 페이지의 본문은 Notion Markdown API로 읽어 요약, 핵심 메시지, 인용문, 적용점, 추천 대상을 추출한다.
3. 동기화 스크립트가 `reading/data/books.json`과 `reading/data/notion-reading.json`을 한 실행에서 생성한다.
4. 변경이 있을 때만 두 스냅샷을 함께 커밋하고 GitHub Pages가 배포한다.
5. 공개 페이지는 노션을 직접 조회하지 않고 JSON 스냅샷만 읽는다.

## 화면 기능

- 598권 전체 검색, 대분류·세부분류·읽음 상태 필터와 정렬을 유지한다.
- `독서기록 있음` 필터와 목록의 `독서기록 보기` 동작을 제공한다.
- 상세 화면에는 기존 서평과 함께 상태, 핵심 메시지, 실제 적용점을 표시한다.
- 공유 해시는 기존 `#book-{독서기록ID}` 형식을 유지한다.

## 운영 순서

1. 이번 배포에서 자동 동기화와 임시 제목 연결을 적용한다.
2. 노션에서 현재 3편의 `독서LOG`/`관련도서` 관계를 연결한다.
3. 이후 새 기록은 관계 속성을 필수로 입력하고, 동기화 경고에서 미연결·중복 후보를 점검한다.
4. 저자·출판사, 표지, 알라딘 링크는 데이터 정비 수준에 맞춰 순차 보강한다.

## 검증 기준

- 공개 도서 598권과 공개 독서기록 3편이 생성된다.
- 세 독서기록이 각각 한 권에 연결되고 `재독` 기록도 노출된다.
- 관계 연결을 우선하며 제목 중복 후보는 자동 연결하지 않는다.
- 검색·필터·정렬·상세 모달·공유 해시가 데스크톱과 모바일에서 동작한다.
- 동기화를 두 번 실행해도 내용이 같으면 생성시각과 Git diff가 바뀌지 않는다.
