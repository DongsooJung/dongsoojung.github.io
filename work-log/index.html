완료 후 · 검증표와 채점 원칙

항목별로 통과 / 일부 통과 / 실패 / 미확인 / 해당 없음을 기록한다. 증거에는 확인 날짜, 대상 버전·커밋, 테스트 결과·화면·로그 등의 위치, 담당자와 남은 조치를 남긴다.

  • 통과는 배점의 100%, 일부 통과는 50%, 실패는 0%를 부여한다. 일부 통과는 충족한 조건과 남은 조건을 함께 기록한다.
  • 미확인은 실패와 구분하며, 확인한 항목만으로 산출한 점수는 반드시 잠정 점수로 표시한다. 해당 없음은 이유를 남기고 평가 배점에서 제외한다.
  • 잠정 점수 = 획득점 ÷ 확인한 적용 항목의 배점 합계 × 100. 검증률 = 확인한 적용 항목의 배점 합계 ÷ 전체 적용 배점 × 100. 전 항목이 확인되기 전에는 최종 점수를 확정하지 않는다.
  • 개인이 직접 코드를 모두 작성할 필요는 없다. 구조를 선택한 이유, 장애 지점과 복구 방법을 설명하고 검토할 수 있는지를 평가한다.
  • AI가 수행하지 못한 검증을 사용자 개인의 역량 감점으로 바로 돌리지 않는다. 산출물 품질과 개인 역량을 구분한다.
  • 배포 요청 접수·빌드 성공·배포 완료·운영 화면 정상 동작을 구분해 기록한다.

기록 양식: 평가 영역 / 항목 / 상태 / 획득점·배점 / 증거·버전 / 확인일 / 담당자 / 남은 조치

적용 원칙: 착수 전 여섯 줄 요구사항과 완료 후 검증표를 남긴다. 이 기록은 평가 기준 수립이며, 개인 역량 점수나 모든 서비스의 검증 완료를 의미하지 않는다.

PRODUCT DECISION · 2026.10.16 · KST

전략 허브: 목적에서 보고서로 바로 이동

문제: 기업 목록과 긴 비교표가 보고서 검색보다 앞에 있어 자료 탐색을 지연시킨다.

목적·대상: 모바일 사용자가 기업 비교·시장 파악·사업 실행·변화 추적 중 필요한 자료에 빠르게 도달하도록 한다.

범위: 목적별 진입점 4개, 보고서 우선 배치, 비교 자료 접기, 빈 결과 초기화. 보고서 43개와 검색·정렬을 유지한다. 개별 보고서 내용과 데이터 수집은 이번 범위에서 제외한다.

판단 근거: 보고서 개수를 늘리기보다 첫 화면에서 선택할 수 있는 목적을 명확히 하고, 상세 비교 자료는 필요할 때 펼친다.

완료 기준: 목적별 링크가 해당 그룹을 열고 이동한다. 기존 검색·필터 상태에서도 이동할 수 있다. 검색 결과가 없으면 초기화해 전체 목록을 복원한다. 기업 목록·비교표와 카드 링크가 보존된다.

검증: 원본 대비 43개 카드의 제목·링크 보존, 목적별 링크 대상 존재, HTML 구조, 탐색 스크립트 문법·동작을 확인한다. 운영 화면·모바일 사용성 확인과 실제 탐색 시간 단축은 별도 검증이 필요하다.
