## 1. API 명세 조사 결과

### 1.1 소상공인시장진흥공단_상가(상권)정보 API

| 항목 | 내용 |
|---|---|
| 제공 | 공공데이터포털 (data.go.kr, 데이터셋 번호 15012005) |
| 제공기관 | 소상공인시장진흥공단 |
| Base URL | `http://apis.data.go.kr/B553077/api/open/sdsc2` |
| 인증 | 공공데이터포털 활용신청 후 발급되는 `serviceKey` |
| 포맷 | JSON / XML (`type` 파라미터), 페이징 (`pageNo`, `numOfRows` 최대 1,000) |
| 갱신 | 분기별 DB 갱신 (분기말 기준) |

**오퍼레이션 구성 (총 18종)**

- **상권 조회 (4종)**: `storeZoneOne`(지정상권), `storeZoneInRadius`(반경상권), `storeZoneInRectangle`(사각형상권), `storeZoneInAdmi`(행정구역상권)
- **상가업소 조회 (10종)**: `storeOne`(단일상가), `storeListInBuilding`(건물상가, key=건물관리번호), `storeListInPnu`(지번상가, key=PNU), `storeListInDong`(행정동상가), `storeListInArea`(상권상가), `storeListInRadius`, `storeListInRectangle`, `storeListInPolygon`, `storeListInUpjong`(업종별), `storeListByDate`(수정일자 기준 증분 조회)
- **업종 분류 조회 (3~4종)**: 대분류(10개) / 중분류(75개) / 소분류(247개) — 표준산업분류(KSIC) 연계 체계

**주요 응답 필드**: 상가업소번호(`bizesId`), 상호명, 업종 대·중·소분류 코드/명, 표준산업분류 코드/명, 시도·시군구·행정동·법정동 코드, 지번주소(PNU), 도로명주소, **건물관리번호(`bldMngNo`)**, 건물명, **층수(`flrNo`)·호수(`hoNo`)**, 경도·위도

**호출 예시**

```
GET http://apis.data.go.kr/B553077/api/open/sdsc2/storeListInDong
    ?serviceKey={KEY}&divId=adongCd&key=1168064000
    &indsLclsCd=I2&type=json&numOfRows=1000&pageNo=1
```

### 1.2 핵심 제약 — 공실률은 API에 직접 존재하지 않음

이 API는 **"현재 영업 중인 상가업소"의 위치·업종 정보만** 제공한다. 공실률 필드, 폐업 이력, 임대 정보는 없다. 또한 API는 **항상 최신 분기 DB만** 조회되므로, 과거 분기는 API가 아니라 공공데이터포털의 **분기별 파일데이터 스냅샷**(`소상공인시장진흥공단_상가(상권)정보_YYYYMMDD`, CSV)으로 확보해야 한다. 최신 스냅샷은 **2026-03-31 기준(2026년 1분기)** 이 확인되었다.

따라서 공실률 분석은 두 축으로 설계한다:

1. **공실 프록시(추정) 지표**: 분기별 상가 DB 스냅샷을 차분(差分)하여 건물·상권 단위 점포 소멸/신생을 산출
2. **실측 공실률 검증 데이터**: 한국부동산원 상업용부동산 임대동향조사 — 분기별 **중대형상가·소규모상가·오피스 공실률(%)** 을 지역/상권 단위로 공표 (공표 시기: 분기 익월 마지막 목요일 → 2026년 1분기치가 2026-04-30 공표, 현재 최신). Open API `한국부동산원_부동산통계 조회 서비스`(15134761) 및 파일데이터 제공

## 2. 분석 프레임: 공실률 정의

| 지표 | 정의 | 원천 |
|---|---|---|
| **점포 소멸률** | (직전 분기 존재 → 당분기 소멸한 `bizesId` 수) ÷ 직전 분기 점포 수 | 상가 DB 분기 차분 |
| **점포 신생률** | 당분기 신규 `bizesId` 수 ÷ 직전 분기 점포 수 | 상가 DB 분기 차분 |
| **순증감률** | 신생률 − 소멸률 | 상가 DB 분기 차분 |
| **건물 단위 공실 프록시** | 건물관리번호(`bldMngNo`)별 점포 수가 감소한 층·호 비율 (호 단위 추적) | 상가 DB (`flrNo`, `hoNo`) |
| **실측 공실률** | 한국부동산원 공실률(%) — 중대형/소규모 상가, 분기별 상권 단위 | R-ONE / data.go.kr |

프록시 지표는 행정동·상권 단위로 집계한 뒤 한국부동산원 실측 공실률과 상관·회귀로 **검증(calibration)** 하여, 실측이 커버하지 않는 세밀한 공간 단위(행정동·건물)의 공실 위험도를 추정하는 것이 최종 목표.

## 4. 파이프라인 설계

```
[수집] 분기별 CSV 스냅샷 + API(최신분기/증분) + 부동산원 공실률 API
   ↓
[정제] bizesId 기준 분기 패널 구축 · 업종코드 표준화 · 좌표/주소 정합성 검사
   ↓
[차분] 분기 t vs t-1 : 소멸/신생/유지 플래그 → bldMngNo·행정동·상권 단위 집계
   ↓
[검증] 프록시 지표 ↔ 부동산원 실측 공실률 상관/회귀 (상권·시군구 매칭)
   ↓
[분석] 시계열 추세(9분기) · 공간 분석(Moran's I, LISA 핫스팟) · 업종별 분해
   ↓
[산출] 정적 JSON 집계 파일 → GitHub Pages 대시보드 (/commercial-vacancy/)
```

**기술 스택 제안**: 수집·정제 Python(pandas, geopandas) — 로컬 또는 GitHub Actions 분기 배치 / 공간분석 PySAL / 대시보드는 본 저장소 관례에 따라 정적 HTML + 지도 시각화(행정동 choropleth, 건물 단위 포인트)

## 6. 리스크 및 유의사항

- **`bizesId` 영속성**: 분기 간 동일 업소의 ID 유지가 전제. 파일럿 단계에서 재부여 여부를 실측 검증하고, 불안정 시 (건물관리번호 + 층·호 + 업종) 복합키로 대체 매칭.
- **소멸 ≠ 공실**: 폐업 후 즉시 새 업소가 입점하면 공실이 아님 → 건물·호 단위에서 "소멸 후 N분기 미충원" 상태를 공실로 정의하는 것이 정확.
- **DB 정비 노이즈**: 공단의 일괄 정비(주소 체계 변경 등)로 특정 분기에 대량 삭제/추가가 나타날 수 있음 → 분기별 총량 변화율 이상치 점검 필수.
- **API 트래픽 제한**: 개발계정 일 트래픽 한도가 있으므로 전수 수집은 파일데이터 우선, API는 조회·증분용.
