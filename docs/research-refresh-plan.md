# 연구 허브 최신화 — 하루 간격 실행

대상은 전체를 포함한 7개 필터, 고유 프로젝트 63개입니다. 연구 난제 7개는 별도 난제·에세이 분류로 점검합니다. 가나다순은 한 필터의 결과 전체를 한 목록으로 정렬하고 한글·영문·숫자 순서로 표시합니다. 연구 허브는 가나다순을 기본값으로 사용하며 정렬 선택은 전략 허브와 별도로 저장합니다. 사용빈도순에서는 기존 그룹 묶음을 유지합니다. 그룹 앵커를 열면 해당 그룹으로 이동합니다.

점검 원장은 `research/data-catalog.json`, 실행 순서는 `research/refresh-plan.json`, 공개 점검표는 `/research/data-review/`입니다. 후속 실행은 원장의 증거와 미완료 단계부터 이어갑니다.

|---|---|---:|
| 0 | 가나다순 적용, 63개 목록, 6개 게시본 초기 점검 | 즉시 실행 |
| 1 | 경제·사회: 무역 수치·범위 불일치, 관광 공표 지연 우선 | 7개 + 6개 |

각 회차는 하루 간격으로 한 묶음을 처리합니다. 실행 중인 회차가 있으면 중복 실행하지 않습니다. 완료한 항목을 다시 훑지 않고 미완료 항목을 이어가며, 접근 실패 항목은 원인과 다음 조치를 기록하고 다음 항목으로 진행합니다.

## 날짜와 완료 기준

- `dataAsOf`·`dataPeriod`: 원자료의 관측 날짜·기간. 월간 자료는 2026-09, 일간·실시간 자료는 실제 확인된 2026-10을 우선합니다. 10월 부분 집계는 완성된 월간 통계로 표현하지 않습니다.
- `collectedAt`: 파일 또는 API가 실제 수집 시각을 제공할 때만 기재합니다.
- `snapshotUpdatedAt`: 게시 데이터 파일에 명시된 갱신일입니다. 자료 기준이나 공식 발표일을 대신하지 않습니다.
- `checkedAt`: 이번 점검 시각입니다. 최신 자료가 있다는 의미가 아닙니다.
- `verified`: 공식 원출처와 데이터·기간·단위·범위를 대조하고 근거 URL을 기록한 경우입니다. 게시본만 읽은 상태는 `snapshot_checked`로 유지합니다.
- 미공표는 공표 일정·최신 공표월의 근거를 남겨 `awaiting_publication`으로, 월 기준을 적용할 수 없는 연구·교육·운영 문서는 실제 문서 버전과 확인 근거를 남겨 `not_applicable`로 기록합니다. 날짜를 임의로 9·10월로 바꾸지 않습니다.

확인한 최신 공식 자료가 있으면 기존 수집·변환 코드를 사용해 데이터와 화면 설명·다운로드·출처를 함께 갱신합니다. 비밀키는 기존 비공개 설정만 사용하며 문서나 로그에 기록하지 않습니다. 무역의 총계와 국가별 범위, 단위, 수출−수입=수지 등 데이터 검증을 통과하기 전에는 값을 덮어쓰지 않습니다.

검증한 묶음은 최신 `origin/main`을 기준으로 해당 파일만 커밋·PR·병합하고 실제 도메인에서 확인합니다. 사용자와 다른 작업의 변경은 보존합니다. 별도 채팅에 메시지를 보내거나 유료 설정을 바꾸지 않습니다. 완료 단계와 배포 근거를 실행 원장에 기록합니다.

브라우저 검증 도구는 작업 폴더의 `verify-research.cjs`입니다. 저장소 상위 폴더에서 `node verify-research.cjs`로 로컬, `node verify-research.cjs https://www.stargateedu.co.kr`로 라이브를 확인합니다. 후속 회차는 점검 수가 늘어난 사실을 실패로 취급하지 않아야 합니다.

변경이 없는 실행은 조용히 마치고, 실제 반영·실패·사용자 조치가 필요할 때만 알립니다. 모든 단계의 근거와 라이브 검증이 끝나면 이 예약을 비활성화합니다. 미공표·접근 제한은 사유와 후속 조치를 남겨 최종 보고합니다.
